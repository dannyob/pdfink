# Toolbar Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace pdfink's wrapping text toolbar with one row of labelled icon tiles in the pen menu's style: the notebook name and current bookmark as menus, grouped tools, a status line underneath, and groups that move into More when the bar is too narrow.

**Architecture:** A new `src/toolbar.ts` builds the bar from data and opens its menus through the app's existing `ContextMenu` (one instance, so one menu open at a time). `ContextMenu` gains labelled tile rows, icons and right-hand detail on rows, indentation, and button-anchored opening that toggles. The current-bookmark rule is a pure function fed by new App state. A pure `fitGroups` decides which groups overflow into More from measured widths. `index.html`'s header shrinks to mount points.

**Tech Stack:** TypeScript, Vite, vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-26-toolbar-design.md` (mockup linked there).

## Global Constraints

- No new npm dependencies.
- Tiles 52 px tall, labelled (icon above an 11 px label), 6 px apart; name and bookmark buttons capped at 190 px and 210 px with an ellipsis. Never drop labels.
- Look, shared by bar and pen menu: resting tile white with a 1 px #8a9099 edge on the #f3f3f1 bar; disabled tile no fill and no edge, icon and label at 35% opacity; selected tile solid #2f4a7a with white; separator a 1 px #9aa0a8 rule 28 px tall with 12–14 px total gap; ▾ in full ink 12 px; current menu entry ticked (✓) with a 3 px ink bar on its left.
- Groups in order: name ▾, bookmark ▾ | Pen, Eraser, Select | Pen style | Copy, Cut, Paste, Delete | Undo, Redo | Add page, Commands, command buttons, run chips … More ⋯.
- Overflow order into More: Add page, then the clipboard group, then Pen style. Name, bookmark, tools, Undo/Redo, Commands and More never leave.
- Status line: messages and progress on the left; save state ("Saving…", "Saved HH:MM", "Unsaved", "Not in notebooks"), the selection count, page count ("page 6 of 19") and "writing on N" on the right.
- Current bookmark: last bookmark (in outline order) whose page ≤ the page the pen last touched; before any pen touch, the one last picked from the Bookmarks menu; before either, the one covering page 1 (page index 0). Scrolling never changes it. `null` → button reads "Bookmarks", greyed.
- Keyboard shortcuts keep working. Tiles that stay on the bar keep their ids (`tool-pen`, `tool-eraser`, `tool-select`, `btn-copy`, `btn-cut`, `btn-paste`, `btn-undo`, `btn-redo`, `btn-addpage`); `#status`, `#progress`, `#cmd-buttons`, `#runs`, `#ctx-menu` keep their ids.
- The repo is public: no personal details. All tests stay green: `npx vitest run`, `npx playwright test`, `npm run typecheck`.

## Review Focus

1. A pen tap on the page that closes an open bar or pen menu must not leave ink (and a finger/palm tap must not act).
2. Tapping a bar button whose menu is open closes it rather than closing and reopening.
3. The bar never wraps to two rows at 947 px and 1267 px wide (the Daylight's portrait and landscape), with long notebook and bookmark names.
4. Browser-only storage: no Commands tile, no dangling separator, File menu shows Open…/New/Save/Save as…/Notebook pages.
5. The current bookmark after deleting or adding bookmarks, after a reload, and in a notebook with no bookmarks.

Each has a test in the owning task.

### Task 1: ContextMenu for the bar, and the shared look

**Files:** Modify `src/menu.ts`, `src/style.css`, `src/icons.ts`. Test: `tests/e2e/menu.spec.ts` (extend).

**Interfaces:**
- Produces:
  - `MenuAction` gains `icon?: string` (SVG markup shown before the label on a text row), `detail?: string` (right-aligned text), `indent?: number` (levels, 18 px each), `current?: boolean` (✓ + ink bar).
  - Row item gains `labelled?: boolean`: `{ kind: "row"; items: IconAction[]; labelled?: boolean }` renders each tile with its label under the icon (class `tile labelled`).
  - `ContextMenu.showFor(button: HTMLElement, items: MenuItem[]): void` opens the menu anchored at the button's bottom-left + 4 px, records the button as owner; a click on the owner while the menu it opened is open closes it (and does not reopen). `ContextMenu.owner: HTMLElement | null`.
  - An outside `pointerdown` that closes the menu is swallowed (`stopPropagation` + `preventDefault` in the capture listener) so it draws, erases or selects nothing.
  - Icons added to `src/icons.ts`: `addPage`, `commands`, `more`, `bookmark`, `bookmarkAdd`, `folder`, `fileNew`, `save`, `import`, `export`, `zoomIn`, `zoomOut`, `fitWidth` (24-unit, `currentColor`, like the existing ones).

### Task 2: The current bookmark

**Files:** Create `src/current-bookmark.ts`. Modify `src/app.ts`. Test: `tests/unit/current-bookmark.test.ts`, `tests/e2e/bookmarks.spec.ts` (extend).

**Interfaces:**
- Produces:
  - `currentBookmark(bookmarks: Bookmark[], inkPage: number | null, picked: number | null): number | null` — index into `bookmarks`. With `inkPage !== null`: the last bookmark in outline order with `page !== null && page <= inkPage`, else `null`. With `inkPage === null`: `picked` if it is a valid index, else the same rule with page 0.
  - App: `inkPage: number | null` (set on every pen or finger-draw stroke start, and by `addStrokes`; reset to `null` on load), `pickBookmark(i: number): void` (scrolls to its page, sets `picked = i` and `inkPage = null`, so the pick shows until the next pen touch), `get currentBookmarkIndex(): number | null`, and AppEvent `"currentBookmark"` emitted with the index whenever it changes (stroke start on a new page, bookmarks changed, pick, load).

### Task 4: Fit the width by moving groups into More

**Files:** Create `src/fit.ts`. Modify `src/toolbar.ts`. Test: `tests/unit/fit.test.ts`, `tests/e2e/toolbar.spec.ts` (extend).

**Interfaces:**
- Produces: `fitGroups(widths: Record<string, number>, available: number, movable: string[]): string[]` — the movable groups (in `movable` order, first moved first) that must leave so the sum of the remaining widths ≤ `available`; `[]` when everything fits.
